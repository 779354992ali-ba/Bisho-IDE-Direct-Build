# Package100 — Local ARM64 engine correctness pass

## Implemented in this branch

1. Separated the Android PRoot launcher from the Linux ARM64 host PRoot used by the packer. The Android binary is checked for AArch64 and the Android `/system/bin/linker64` interpreter; it is never executed on the Linux packaging host.
2. All rootfs smoke commands use the separately installed host PRoot, with an optional `BISHO_HOST_PROOT` override.
3. Added explicit prerequisites for `readelf`, `timeout`, and a native Linux ARM64 host PRoot.
4. Corrected storage guidance to match the current native 2.5 GiB build preflight; it is a minimum starting threshold, not a promise that every project fits.
5. Marked the ARM64 toolchain plan as reference-only and aligned its known community-tested Debug baseline to Flutter 3.27.4, API 35, and Build Tools 35.0.1. No runtime bundle is claimed or generated by this change.

## Verification limits

- Source review only; GitHub Actions, Flutter analysis, Kotlin compilation, packer execution, and physical-device tests have not yet run.
- A Linux ARM64 host and separate Linux PRoot are still required to execute the guest smoke build.
- The Android PRoot binary still requires real-device ptrace/rootfs/bind-mount validation.
- SDK license acceptance must be performed by the publisher/user under applicable terms.
- Release/AOT remains disabled until a real Release build passes.
